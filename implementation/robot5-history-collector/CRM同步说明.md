# 机器人5问答到移民CRM

同步功能在现有 `collector.py sync` 内执行，不经过 Excel，也没有第二套部署服务。使用相同的本地问答档案，CRM 的队列和行ID映射保存在同一个 SQLite 中。现有消息主键、版本和 Excel 格式不改变。

2026-10-19 已开启：已补传234组完整问答，每条写入后回读核对；包含约28万字的最长执行过程，初始评分为“未评分”。原有每60秒运行的采集任务已恢复，并在同一程序内持续同步CRM。“提问人”为文本，按用户决定直接保存企微用户标识。最新数量与状态以档案目录的`CRM同步验收.json`、`CRM试点验收.json`及`crm-health.json`为准。

核验更正：明道云表单的必填不强制适用于API写入，因此程序不再把“评分必填”当作API阻塞。存在“未评分/待评分”选项时，新增记录明确写入该选项的名称（V2接口的赋值方式），不冒填0—4分；原有实际评分、评测备注、时间和人员均由人工维护。

## 数据与完整性

- 提问时间：北京时间，年月日时分秒。
- 提问人：企微用户标识，无明道成员映射。
- 问题、答案、推理过程：使用本地档案的完整原文/执行记录文本，不依赖 Excel 的显示或分片。原文同步写入“答案（原始格式）”；每轮按当前字段名称解析字段ID。
- 回读逐字段核对。实测明道 V2/V3 会移除答案末尾 ASCII 空格：仅允许这一种平台格式差异，并在 SQLite `crm_records.readback_note` 记录去除字符数及双方哈希；本地原文不变。正文、换行、问题等其他差异仍阻塞，不能当作原文完全一致。全量核查报告单列此类记录。
- 来源记录ID：`robot5:{channel_id}:{assistant_message_id}`。
- 人工评测字段：新增时只设置“未评分”标记；后续不写实际评分、备注、评测时间和评测人。已经评分的答案发生来源变化时进入待复核阻塞状态，不自动覆盖。“未评分”不会被误判为已人工评测。
- 每次写入后通过API回读比对所有同步字段；发现截断、格式变化或内容不一致时不会标为成功。超长内容是否可直接写入必须在真实最长记录的试点中核验；不允许静默截断。
- 仅发布已完成、问题与答案配对明确的记录。源删除或未完成记录不触发CRM删除，已有CRM记录保留。

## 去重和故障恢复

SQLite `crm_records` 保存目标范围、来源键、CRM行ID、内容指纹、状态、重试次数和下次重试时间。没有变化的记录不再写入。

上传顺序：新增或发生内容变化的待同步记录，按提问时间从早到晚上传；不同时间区偏移转换为实际时间比较，同一时刻按来源ID稳定排序。达到单轮条数/时间限额后，下轮继续这一顺序。失败记录等待重试时间，到期后在本轮新增队列之后单独重试，避免旧失败记录挡在新问答前面。此规则不重排已上传记录，也不修改用户自行设置的CRM视图排序。

新增前按来源键回查。使用V2列表接口、指定视图和文本精确匹配筛选器（`dataType=2, filterType=2`）；返回字段的别名统一还原为字段ID后比较。写入成功但客户端超时时，下轮先回查已经生成的行，避免盲目重复新增；服务端唯一来源字段提供最后一道保护。API返回行ID后立即持久化，再回读验证。失败只保存错误码，不记录凭据、问题和回答正文。

每轮默认最多处理10条、20秒预算，网络单次超时默认10秒；失败重试逐步退避。CRM失败不会让已成功的问答采集失败；Excel导出失败也不会阻止CRM读取已经入库的问答。两者的状态分别由 `health.json` 和 `crm-health.json` 表达。

## 新增问答的同步时序

任务按60秒周期触发，属于轮询，不是回答结束时的事件推送；上一轮尚未结束、网络或Excel导出耗时都会影响实际采集间隔，不承诺严格60秒以内。

当前时序为：采集并提交本地数据库 → CRM原文与网页同步 → 请求后台Excel导出。正常新增记录会在同一次新增API请求中携带原始答案和网页HTML，避免先出现原文、再等待排版队列。转换异常时先保全原文，网页队列单独阻塞并记录原因；后续修复已有网页内容仍只写网页列，不覆盖人工评测。

当前已启用 `binding.export_async=true`：后台导出使用独立文件锁和一致的数据库快照，原采集进程不再等待Excel，也不再持有整个导出期间的读取事务。只有一份Excel导出在运行，期间新增数据合并到下一次导出。失败保留上一份有效工作簿，并在 `excel-health.json` 持久记录错误类型和退避时间。人工导出和迁移快照会等待同一导出锁。迁移恢复后也默认开启后台导出，无需额外安装定时服务。

当前私有CRM配置单轮处理上限由10提高到30，原文、网页各自的20秒实际处理预算及请求间隔保持不变；仍按原有时间顺序和重试规则执行。上限不是强制处理30条，预算耗尽时保留队列。

网页HTML按原文哈希和格式版本持久缓存在 `crm_web_records`，跨进程重启复用，只有新答案、原文变化或版本变化才重新转换。规划阶段与实际上传预算分开，避免准备工作耗尽预算导致连续多轮处理0条。状态增加 `planning_seconds` 和 `ready_before_run`，原文阶段增加 `created_with_web` 便于核验两列同次写入。

## 网页答案自动排版

统一标准现为 v2，详见 [网页展示规范](网页展示规范.md)。正文只生成HTML片段，统一字号、行高与表格样式；引用转为编号和文末资料名称，技术ID保留在原始答案中。输出增加版本标记，并核对源文字和引用资料没有遗漏；每条异常单独阻塞，不向网页列写入错误占位文本。

2026-10-23 实际核验“答案（网页格式）”为富文本字段（type 41）。`answer_format.py` 将本地答案 Markdown 确定性转换为 HTML，支持标题、加粗、列表、表格、换行和链接，不调用模型改写。输入中的 HTML 按文字转义，危险协议链接不可执行。纯 Python 解析器 Mistune 3.1.3 随 `_vendor/` 提供，许可证保留在其中，无需目标电脑另外安装。

`crm_web.py` 在相同采集进程、相同文件锁内运行，但使用 SQLite `crm_web_records` 独立排队；只处理已完成原文同步的问答，按提问时间排序。新增网页答案默认每轮最多10条、20秒预算（`web_budget_seconds` 可配置），单次请求超时及失败退避沿用CRM配置；原文和网页阶段分别预算。状态位于 `crm-health.json.web_format`。

每条先回读确认来源ID及原文，再仅写“答案（网页格式）”一个字段，并回读核对HTML及其他字段未变。已经评分的记录也可补齐空白网页内容，不会因此重写原文或评分。首次发现已有网页内容、或生成后被人工修改的网页内容，标为 `preserved` 保留，原因记录为 `existing_or_manually_changed_web_answer`；网页阶段显示 `needs_review`，不算作统一格式成功。只有此前由本程序生成且未被改动的网页内容，才随原文或格式版本更新而重新排版。重复运行无变化时不写入；写入超时后通过回读恢复，不新增CRM记录。此次已依据异常快照重建原有5条错误格式记录，旧内容另有备份；此修复不会扩大为后续任意覆盖人工网页内容的权限。

网页队列和原文队列在同一个数据库中，现有迁移快照会一并携带；代码迁移时须完整包含 `answer_format.py`、`crm_web.py` 和 `_vendor/`。原始JSON和Excel的格式及内容均不受网页排版影响。

## 私有配置和迁移

私有配置为问答档案目录内的 `private/crm-config.json`，目录0700、文件0600。包含应用授权、工作表及视图ID、`enabled` 开关、超时和单轮限额。密钥不写进源代码、日志或验收输出。

迁移时沿用现有档案快照：问答、CRM同步状态和私有配置一起进入迁移包。部署包需保持既有加密保护，不能把包含私有配置的档案作为普通附件对外发送。旧采集电脑在正式切换时停用，避免两台电脑同时成为写入端。

## 命令

```sh
# 读取结构与列表权限，检查字段要求；无CRM写入
python3 implementation/robot5-history-collector/collector.py crm-check

# 只有用户明确同意字段设置变化后执行
python3 implementation/robot5-history-collector/collector.py crm-prepare --approve-field-changes

# 指定少量真实问答试点。该命令允许在enabled=false时手动验证写入
python3 implementation/robot5-history-collector/collector.py crm-sync --crm-limit 3 --crm-budget 60

# 本地状态
python3 implementation/robot5-history-collector/collector.py crm-status
```

字段核验、真实长文本回读和重复运行测试通过后，将私有配置的 `enabled` 设为 true（当前已开启）。原来每分钟运行的 `sync` 自动执行采集、导出和CRM同步。需要停止CRM同步时只把该开关设为 false，本地采集与Excel导出继续运行；不要删除去重映射或私有配置。
