# 机器人5部署与日常运维手册

版本：2026-10-20。本文覆盖当前Mac运行方式、新Intel Mac预部署、正式切换及重启故障处理。运行数量和健康结论以当天报告、health与平台回读为准，不把旧截图当实时状态。

## 1. 服务清单和依赖

| 功能 | 内容 | 运行方式 |
|---|---|---|
| 微盘来源采集 | 企业微信将目标目录下载到本地 | 企业微信桌面客户端及微盘同步进程 |
| 来源同步与解析 | 新增、修改、改名、缺失检测；Markdown发布与索引验证 | 1个常驻同步worker |
| WeKnora知识库及问答 | 管理、切分、索引、检索、问答、企微渠道 | 7个Docker服务 |
| 大文件压缩 | 原件备份、压缩回写、客户端确认、恢复及异常记录 | 3个定时任务 |
| 问答档案及CRM | SQLite增量归档、执行过程、JSON/Excel导出、CRM直连同步 | 1个每60秒任务 |
| 日志和问题清单 | 文件原因、阶段、重试、恢复、预算与请求结果记录 | 集成于上述程序；不另建日志平台 |

7个WeKnora服务：frontend（管理网页）、app（业务/检索/问答/渠道）、docreader（平台读取解析）、postgres（业务与检索数据）、redis（缓存/任务协调）、neo4j（图谱能力）、bailian-asr（百炼语音适配）。容器运行不证明机器人实际问答已经通过验收。

5个自建后台任务是：同步1项、问答/CRM采集1项、压缩/恢复/异常检查3项。日志和解析不是另外两套常驻服务。跨机SFTP采集接收、对账、迁移、打包工具只在明确调用时运行，当前来源模式为local。

运行前提：电脑开机、保持唤醒、用户登录；企业微信已登录且目标目录启用同步；Docker可用；模型/CRM访问网络及相应授权有效。新Mac需要Intel版Docker Desktop、Python3.12、OpenSSL3、LibreOffice、Poppler及requirements中的库。目标系统及依赖以新机实测为准；本包做过Python3.12/Intel wheel可用性和7镜像linux/amd64清单检查，没有替代真实Intel安装。

企业微信扫码、账号授权和系统交互由用户完成；不要复制旧机客户端登录态或把旧账号缓存数据库当新账号使用。当前账号仅能处理实际落地的文件，下载占位或仅在线内容不能当作已取得原件。

## 2. 来源和数据流

微盘 → 企业微信本地「项目to咨询」 → 稳定扫描 → 原件快照及指纹 → 解析或复用已验证结果 → Markdown → WeKnora上传/去重 → 索引及检索验证 → 机器人5。

来源基准是微盘本地同步目录；Markdown及知识库是下游。支持同内容多路径共享知识，来源数量与知识条目数量不同不直接等于丢失或重复。映射保留来源ID、路径、内容版本、Markdown指纹、知识ID和共享引用。

当前来源范围：「项目to咨询」及子目录。当前压缩范围：「项目to咨询/售前文档」，并非整个来源根目录。新机要分别核对同步配置和压缩配置；预部署包保留的旧压缩档案及范围可能早于现机，不能凭本文直接启用正式压缩。

## 3. 参数和更新行为

| 项目 | 当前旧机配置 | 新机预部署 |
|---|---|---|
| 轮询 | 60秒 | 绑定后核对实际config.json |
| 内容稳定等待 | 180秒 | 沿用包配置并核对 |
| 每轮新任务上限 | 6个 | 核对生成配置 |
| 自动删除 | 已启用，连续3次完整缺失扫描且至少60秒 | 保持关闭，正式接管后按验收启用 |
| 大量缺失阈值保护 | 按用户要求关闭 | 以实际配置为准，不擅自变更 |
| 无文字 | 确认后默认跳过，保留原件和结果 | 同样规则 |
| 同步/压缩弹窗 | 已关闭，保留日志和问题清单 | 核对生成配置，不把历史submitted当最新开关 |

轮询不是更新完成时限。还需企微下载、180秒稳定等待、解析、上传及索引；频繁保存会重新计算稳定等待。修改配置后通常要平滑重启相应服务，保存配置不等于进程已加载。

解析优先复用已验证结果和响应；PDF特定结构错误可生成独立兼容副本，密集Excel和大图片可分区，WPS checkbox可保留静态图片并直接提取保存的勾选值。最终正文缺少状态会阻止发布。不执行控件，不把未知控件、损坏或不完整正文冒充成功。

无文字只适用于解析链已判定NO_READABLE_TEXT的整个文件；漏页、缺正文、模型超时、结果未知不归为无文字。同一已跳过版本不重复解析，内容变化后重新判断。旧结果与失败历史保留。

新版本验证后再清理旧知识；解析失败时保留已有活动版本。模型结果未知时禁止盲目重发，预算和请求账本随parse-runtime迁移，不能通过新建任务或清空状态绕过。

## 4. 压缩、问答及CRM

压缩仅处理授权范围内大于30,000,000字节的受支持PDF、DOCX、PPTX、XLSX；先保留原件，再验证副本、回写、核对客户端文件身份、版本、MD5及大小。需要编辑权限；能下载不等于可以回写。客户端缓存/回执确认和独立云端读回是不同证据，不宣称所有客户端记录都已经独立云端核验。

压缩计划：每日北京时间03:00；每120秒恢复未完成任务；每300秒只读检查异常。定时任务两轮之间显示not running不一定异常，应看最后退出码、计划和最近记录。压缩回写不能与同步worker读取同一个来源快照互相竞争，沿用既有写入锁协议。

问答采集每60秒从WeKnora数据库增量读取机器人5企微渠道问答及执行过程，保存SQLite和历史版本，JSON/Excel为派生导出。CRM直接从SQLite同步，不经Excel。保存来源键、CRM行ID、指纹和去重状态；已评分记录不自动覆盖，源问答删除不传播CRM删除。

本预部署包恢复时CRM写入有强制门禁，普通采集和force试点都不能绕过；正式最终包通过activate既有检查后恢复原开关。不得在两台电脑同时启用正式机器人渠道或CRM写入。

## 5. 日常检查与文件位置

| 项目 | 当前项目目录内 | 新机安装目录内 |
|---|---|---|
| 同步配置 | .local/weknora-sync/config.json | config.json |
| 同步状态/映射/预算 | .local/weknora-sync/live/ | state/ |
| 已解析Markdown | 以配置markdown_root为准（当前在桌面当前解析结果下） | markdown/ |
| 同步当前问题 | live/failure-alerts/当前问题.md | state/failure-alerts/当前问题.md |
| 持久日志 | live/logs/audit与runtime | state/logs/ |
| 问答及CRM健康 | outputs/机器人5历史问答采集/health.json、crm-health.json | history-archive/下同名文件 |
| 问答/CRM去重档案 | outputs/机器人5历史问答采集/history.sqlite3 | history-archive/history.sqlite3 |
| 压缩结果与备份 | outputs/售前文档定时压缩_20261019/registry/；旧档案也保留 | compression/registries/，以迁移配置为准 |

先检查health时间是否更新，再读状态、当前问题和对应文件报告。不能只看容器healthy或launchctl的PID就认定同步成功。桌面提醒当前关闭，要查看日志；历史记录中的旧路径、submitted事件不等于当前服务仍使用该路径或已显示横幅。


大文档解析期间，health可能要到整轮结束才更新时间；应结合state中的parse_intent、任务报告/请求收据的最新时间和日志判断是否仍在推进。不要仅因health暂旧就强杀进程或重发模型请求。

新机只读检查示例（不要对错Compose项目执行停止或恢复）：

```sh
docker compose -f "$HOME/Robot5-stage/private/platform/compose.json" ps
cat "$HOME/Robot5-stage/state/health.json"
cat "$HOME/Robot5-stage/history-archive/health.json"
cat "$HOME/Robot5-stage/history-archive/crm-health.json"
```

需排查单文件时沿用worker的trace/export-logs入口，不在聊天、工单或普通日志中贴API Key、模型密钥或CRM签名。私有文件0600，目录0700。

## 6. 重启、ROOT_UNAVAILABLE与安全恢复

2026-10-20实测：Mac于10:47重启，后续来源目录路径和inode不变，但st_dev从16777232变为16777233，旧的「设备号+inode」校验触发ROOT_UNAVAILABLE。这个错误也可能表示目录缺失或被替换，不能每次都当作正常重启。

处理顺序：

1. 保持已有知识和映射；查看health、根目录和企微登录/同步进程。记录重启时间、realpath、目录inode及当前挂载卷UUID，区分缺失、无权限、占位和身份变化。
2. 核对完整受支持来源清单及指纹，列出新增、修改、缺失与既有排除项。inode相同或搜索不到文件都不能单独当作确认；不直接放开大量删除。
3. 确认只是设备号变化且目录内容可核验后，正常停止worker派发并等待退出，避免launchd抢先重启；取得worker.lock，备份state和config后再恢复目录身份。
4. 保留全部来源ID、知识ID、待处理任务、共享引用、原件与历史结果。清除旧缺失计时，防止暂停时间抵充删除等待。已做全量内容证明且inode/大小/mtime一致的属性缓存可仅重绑定设备号；其他缓存重建并等待稳定。
5. 启动原worker，确认保护解除、扫描推进，再核对暂停期间变更、索引/下载/检索及删除备份；不要启动第二个writer，也不要清空state重建映射。

本次执行的是有证据的一次性身份恢复；当前根目录校验仍保留，未来重启遇到同类情况应按此核验。不能宣称已经实现跨重启自动重绑。

当前删除依赖本地连续缺失，而不是独立云端删除核验。大量缺失阈值保护被关闭，取消子目录同步、撤权或分批缺失仍可能误传播删除。已有根目录/占位检查、备份和共享引用保护不等于完整防误删，也没有一键恢复全部来源原件的能力。发现异常应先暂停传播并保留证据，不通过缩短等待或空状态绕过。

## 7. 新Intel Mac的安装与验收顺序

1. 分别拷贝ZIP与匹配unlock.key，运行SHA256校验。解锁文件不在ZIP中，不与包一起公开分发。旧版本保留；新安装使用全新~/Robot5-stage，不覆盖~/Robot5。
2. 按开始部署.md安装依赖并setup，只解密和安装；此时不启用正式业务。
3. restore恢复本包自己的Compose项目。机器人渠道关闭，自动删除关闭，CRM门禁保持关闭；确认7服务运行、网页可访问、资料可下载。
4. start-history恢复问答/CRM映射并作全量去重核对，确认两份health时间推进。没有真实外部写入时不能宣称CRM新机写入验收已完成。
5. 登录专用企微账号，下载目标目录，使用实际路径执行bind。旧机账号目录、缓存路径不能照搬。若本包旧快照与当前微盘有差异，bind应阻塞并报告；不能清空映射、伪改指纹或删除新文件来强行通过。预部署可以先验环境和历史恢复，正式数据对账需最新冻结包。
6. 仅在来源对账通过后start-sync。验收新增、修改、改名、无文字跳过、WPS状态、异常留旧版和检索；删除测试只用专用测试文件，并核对备份和共享引用。隔离样例或合成测试不冒充真实企微问答。
7. 正式接管完成后才绑定专用企微缓存并启用压缩，先用授权测试文件核对回写和客户端读回。旧机和新机不能同时压缩相同范围。

## 8. 预部署、最终冻结和正式接管

本包程序和问答/CRM档案更新到2026-10-20，平台、原映射及压缩档案仍是2026-10-16的完整快照。没有暂停线上服务生成新的平台快照，因此它不是当前线上全量最新数据。

预部署用于安装、恢复和验证环境，不能activate接管。正式迁移时，先让旧机任务尽量收敛，获准短暂停写后，用本包新版build_mac_bundle工具分别指定实际运行项目（--project-root）和本包app（--code-root），生成最新最终冻结包；停止旧机正式服务并保存交接证据。具体命令与恢复/回退步骤见开始部署.md。

新机从最终包恢复到全新正式目录，保留知识ID、映射、Markdown、原件备份、解析缓存/预算、问答/CRM映射及私有配置。核对健康和来源后才能activate；再做真实企微问答、引用、采集与CRM读回、新增/修改/删除验收。新机实际权限、登录、网络和交互尚未由旧机隔离测试证明。

回退先停新机相关服务，保留新机期间新增数据，再恢复旧机；当前没有自动合并两端数据库的工具。不要执行down -v或删除卷，不要同时启用两个正式机器人。
