# 表格原件直传

`config.json` 中 `parser_skip_extensions` 为自建解析的跳过清单，目前配置 `.csv`、`.xlsx`、`.xls`。这些来源仍由同步服务维护映射和新增、更新、改名、删除，只跳过自建解析和 Markdown 生成。WeKnora 接收原始文件后继续执行平台解析、切分、索引。

## 发布和迁移

现有 Markdown 表格分批迁移。旧知识保留至原件上传完成、原件下载摘要匹配、原生单元格/工作表/已保存复选框状态覆盖检查和定向关键词检索通过。随后切换映射，检查共享引用，再备份清理旧知识；原 Markdown 移入历史区，不再参与检索。原始来源文件不修改。失败时保留旧知识，记录 `original_ingest_hold` 和验证报告，不回退到自建 Markdown 解析。

原件快照、验证报告、来源摘要和知识 ID 保存在现有状态目录。`direct_report_path` 指向验证证据，`original_artifact` 指向上传快照，`ingest_mode=original` 表示已完成切换。

## 环境和维护

沿用现有 worker、API key、锁、重试、共享引用和旧版清理。新增 `table_docker_binary` 指向 Docker CLI，`table_docreader_container` 指向平台文档读取容器；部署迁移需按目标机重新绑定。XLS 读取依赖 `xlrd==2.0.2`。

平台原生 Excel 读取增加工作表标签和 WPS 复选框保存状态提取；保留 N/A 文本、编号前导零及 Excel 错误值，并在内存副本中兼容 WPS 空填充样式，通过 Compose 只读挂载交付；升级 docreader 镜像时需重新回归这两个文件。上传保留原件二进制，公式、图片等仍留在原文件中；检索内容核验覆盖原生缓存单元格、工作表和已保存复选框，不代表图表或嵌入图片已 OCR。

`direct_migration_jobs_per_cycle` 控制每轮启动的存量迁移任务数，不改变普通文件的轮询与稳定等待。配置修改后平滑重启服务生效。待处理上传继续在后续轮询中核验。

索引核验按片段位置重建重叠文本，避免重叠切分造成完整单元格匹配误报；数值只接受等值 Decimal 或相同 binary64 的非整数表达，不使用宽泛的金额近似容差。

无文字或空表仍按内容检查结果保留原件，不把缺正文误判为成功。本次范围仅 CSV、XLSX、XLS，其他后缀沿用现有流程。当前来源没有 CSV，CSV 已使用隔离样例验证，不声称已在真实知识库验收。

当前旧 Intel Mac 大部署包并不因工作目录代码变化而自动更新，重新制包时需包含本文所列模块、依赖、配置及 docreader 只读挂载文件。
